# Native Execution Plan

For implementation or repair, initialize the runtime-native plan before the first product write. Do not ask the user for permission to self-organize.

## Runtime selection

- Use `update_plan` when available.
- Otherwise use the runtime's tasks or todos.
- If no native mechanism exists, maintain the equivalent concise checklist in the working response.

This is execution planning, not a request to switch the host into a special Plan mode.

## New-behavior plan

Create compact items equivalent to:

1. Hydrate authority, profile, assignment, graph, and dirty state.
2. Compile Green Contract: basic plus adversarial.
3. Prove all required new L1/L2/L3 rows RED.
4. Freeze the contract by stable ID/hash.
5. Implement compiler/lowering and product changes, then run fidelity-ordered GREEN.
6. Run affected standing, live, cleanup, and resource-delta gates.
7. Register evidence and inspect scoped state.
8. Stop at `READY_FOR_REVIEW` for the canonical directive, or the explicit legacy assignment marker `READY-FOR-AUDIT`, without self-certifying.

Expand a plan item only when the runtime benefits from separate L1, L2, or L3 progress. Every required layer must remain visible. An N/A layer remains visible with its profile reason.

## Repair plan

For failed-only repair:

1. Hydrate verdict, affected graph, locked greens, and retry boundary.
2. Reproduce the exact failed row.
3. Confirm contract integrity and repair authority.
4. Repair only the failed or transitively affected seam.
5. Run selected affected layers and cleanup.
6. Register evidence and stop at the declared boundary.

Do not recreate the full new-feature lifecycle when the immutable assignment authorizes a narrower failed-only repair.

## State law

- Keep exactly one task `in_progress`.
- Keep Web, Android, iOS, and reconciliation visible when the selected profile requires full cross-platform L3.
- Do not mark a RED task complete because files exist.
- Do not mark GREEN complete without the exact selected Nx evidence.
- Do not paste the full Green Contract into plan state; reference its ID/hash.
- Do not hide missing layers inside a generic “tests” item.
- A `layer` assignment cannot report feature completion.
- Stop when authority, scope, version, retry, or evidence is unresolved.
