# COMMAND-SLIM — Minimal 5-Section Worker Contract

> **For dispatch lane (haiku) workers.** Use this template when spawning
> a single bounded mutation to a tier-aware runtime via `aes-summon`.
> For architect → implementer handoffs, use the full `process/command`
> SKILL.md (evidence-grounded-goal-charter).

## 1. IDENTITY

```
dispatch_id:      <UUID, generated by command-generate.py>
tier:             <tier-0 | tier-1 | tier-2 | tier-3 | tier-4>
worker_profile:   <codex profile name OR opencode --model string>
spawned_by:       <aes-summon | Fable 5>
campaign:         <campaign id, e.g., fable5-non-compiler-routes>
route:            <route, e.g., /about (omit if not route-scoped)>
```

## 2. MISSION

```
<intent — one sentence. What the worker must produce.>
```

## 3. SCOPE

```
write_to:
  - <absolute file path 1>
  - <absolute file path 2>

read_from (evidence sources):
  - <absolute file path A>
  - <absolute file path B>

out_of_scope (MUST NOT touch):
  - <forbidden path 1>
  - <forbidden path 2>
```

## 4. MUTATIONS

```
1. <bounded operation — what the worker should change>
2. <bounded operation>
```

## 5. VALIDATION

```
- <command>: <expected exit code>
- <command>: <expected exit code>
```

## 6. OUTPUT CONTRACT

```
On success:
  print "COMPLETE: <1-sentence summary of what changed>"
  exit 0

On halt:
  print "HALT: <reason — specific file:line or missing input>"
  exit non-zero (1 = generic halt, 2 = scope drift, 3 = validation failed)
```

## EXECUTION LAWS (immutable)

- **NO_INFERENCE** — do not invent missing requirements, files, APIs.
- **NO_SCOPE_DRIFT** — do not modify files outside `write_to`.
- **NO_PARTIAL_OUTPUT** — do not claim COMPLETE unless all VALIDATION
  commands pass.
- **EVIDENCE_REQUIRED** — every COMPLETE claim must cite the changed
  files (relative paths) and the validation output.
- **DETERMINISTIC_ORDER** — prefer smallest safe change set in
  dependency order.
- **PRESERVE_EXISTING_CONTRACTS** — do not break public APIs, schemas,
  tests, or runtime contracts.

## BOUNDARIES (HALT conditions)

HALT immediately if any boundary is crossed:
- `WRITE_TO_FILES_OUT_OF_SCOPE` — touched a file not in `write_to`
- `MISSING_REQUIRED_CONTEXT` — read_from path doesn't exist
- `VALIDATION_BLOCKED` — validation command can't run (env issue)
- `TEST_FAILURE_UNRESOLVED` — validation command exits non-zero
- `DESTRUCTIVE_OPERATION_REQUIRED` — would need `rm -rf`, `git push --force`, etc.

## Auto-derived (set by command-generate.py)

The following fields are auto-populated by the script — you do NOT
need to write them in the intent:

- `dispatch_id` — uuidgen
- `out_of_scope` — from the campaign charter's forbidden write list
- `read_from` — 1-hop import graph expansion from the `file_target`
- `worker_profile` — derived from `tier` via the tier table
- `max_runtime_seconds` — tier default (tier-0/1: 600, tier-2: 1200,
  tier-3: 1800, tier-4: 3600)
